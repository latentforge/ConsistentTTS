A. 이미지 생성 분야의 Instruction Following 평가

요약

  • 이미지 생성 분야에서는 프롬프트를 하나의 문장으로만 보지 않고, 작은 조건들로 분해해서 평가함

예시

“빨간 모자를 쓴 강아지가 파란 공 옆에 있다.”

이 문장은 다음 조건들로 나눌 수 있음.

  • 강아지가 있음
  • 모자가 있음
  • 모자가 빨간색임
  • 공이 있음
  • 공이 파란색임
  • 공이 강아지 옆에 있음

평가 방식

  • 객체 존재 여부 확인
  • 색, 형태, 재질 등 속성 일치 확인
  • 객체 개수 확인
  • 위치 및 관계 확인
  • 긴 프롬프트의 여러 조건 충족 여부 확인

관련 Benchmark

  • GenEval
    • 객체, 개수, 색, 위치 중심 평가
  • T2I-CompBench
    • 속성 결합, 공간 관계, 복합 구성 평가
  • DPG-Bench
    • 긴 프롬프트를 object–attribute–relation 단위로 분해
  • TIFA / VQAScore
    • VQA 모델을 사용해 이미지가 텍스트 조건과 맞는지 확인

정리

  • 핵심은 “좋은 이미지인가” 하나만 보는 것이 아니라, 프롬프트 안의 조건을 나누어 확인하는 방식임

B. VA Prediction

요약

  • VA Prediction은 감정을 이름이 아니라 좌표로 평가하는 방식
  • “happy / sad / angry”처럼 감정을 한 단어로 맞히는 대신, 감정이 어느 방향에 가까운지 수치로 예측

핵심 축

  • Valence
    • 긍정 ↔ 부정
  • Arousal
    • 차분함 ↔ 흥분됨
  • Dominance
    • 약함 ↔ 강함

동작 방식

음성
→ speech encoder
→ 음향 특징 추출
→ regression head
→ V / A / D 점수 예측

평가 방식

  • 주로 CCC, Concordance Correlation Coefficient 사용
  • 예측값과 정답값의 상관관계 확인
  • 예측값의 평균과 분산이 정답 분포와 비슷한지도 함께 확인

관련 Benchmark

  • MSP-Podcast
    • 자연스러운 podcast 음성 기반 V/A/D 예측
  • AVEC
    • 시간에 따라 변하는 arousal / valence 예측
  • MSP-Conversation
    • 대화 상황에서 시간적으로 변하는 VAD annotation 제공

정리

  • VAD는 감정을 연속적으로 보기 위한 좌표
  • 다만 이 좌표는 음성의 acoustic cue에서 추정된 값
  • 따라서 VAD를 사용할 때는 어떤 음향 단서가 VAD 예측에 반영되는지 함께 봐야 함

C. Emotional TTS에서 감정 조건을 다루는 방식

요약

  • Emotional TTS에서는 감정을 하나의 방식으로만 넣지 않고, 목적에 따라 여러 방식으로 조건화

대표 방식

  • Emotion label 기반 제어
    • happy, sad, angry 같은 감정 이름을 조건으로 사용
    • 이해하기 쉽지만 세밀한 강도와 중간 감정 표현이 어려움
  • VAD / EASV 기반 제어
    • 감정을 Valence, Arousal, Dominance 좌표로 표현
    • EmoSphere++와 ECE-TTS에서 사용
    • EASV는 VAD 좌표를 구면좌표로 바꾸어 감정 방향과 강도를 다룸
  • Emotion reference 기반 제어
    • 감정이 담긴 reference speech를 넣고, 그 말투를 따라가게 함
    • 감정 label 없이도 다양한 표현을 가져올 수 있음
  • Time-varying emotion 기반 제어
    • 한 문장 안에서 감정이 변하는 경우를 다룸
    • Laugh Now Cry Later / EmoCtrl-TTS에서 arousal-valence trajectory와 non-verbal cue를 사용함

정리

  • 감정 조건은 label, 좌표, reference, 시간 변화 등 여러 수준에서 다룰 수 있음
  • 어떤 방식을 쓰는지에 따라 평가해야 할 조건도 달라짐

D. Speaker / Style / Emotion 정보를 나누어 다루는 방식

요약

  • 관련 논문들은 speech를 보통 내용, 화자, 감정/스타일로 나누어 다루려 함

각 요소의 역할

  • Text / content representation
    • 무엇을 말할지 담당함
  • Speaker embedding
    • 누구의 목소리인지 담당함
  • Emotion / style embedding
    • 어떤 말투나 감정으로 말할지 담당함

왜 추가 장치가 필요한가

  • 실제 음성에서는 정보가 완전히 분리되어 있지 않음
  • 예를 들어 pitch는 화자 특성일 수도 있고 감정 표현일 수도 있음
  • energy, speaking rate, duration, timbre도 비슷하게 여러 정보에 동시에 관여함

대표 장치

  • Orthogonal loss
    • speaker embedding과 emotion embedding이 비슷한 정보를 담지 않도록 학습
    • 예: speaker embedding 안에 angry 정보가 들어가는 것 줄이기
  • Disentanglement module
    • 화자, 감정, prosody 같은 정보를 서로 다른 표현으로 나누려는 모듈
    • 목적은 한 embedding이 모든 정보를 한꺼번에 들고 가지 않게 하는 것
  • Emotion-invariant speaker representation
    • 같은 화자가 다른 감정으로 말해도 speaker embedding이 비슷하게 나오도록 학습함
    • speaker verification 분야에서 사용됨
  • Speaker similarity / emotion similarity 동시 평가
    • 생성 음성이 같은 화자로 들리는지와 목표 감정으로 들리는지를 따로 확인함
    • 하나가 좋아질 때 다른 하나가 나빠지는지 확인 가능함

정리

  • encoder를 나누는 것은 출발점
  • 이후에는 각 embedding이 어떤 정보를 실제로 담는지 확인하는 평가가 필요함

E. 조사 논문들에서 가져올 내용

EmoSphere++

  • zero-shot emotional TTS 모델
  • speaker encoder와 emotion encoder를 분리함
  • VAD를 EASV로 바꾸어 감정의 style과 intensity를 조절
  • speaker / emotion embedding overlap을 줄이기 위해 orthogonal loss 사용

ECE-TTS

  • F5-TTS 기반 zero-shot emotional TTS 모델
  • pretrained emotion recognizer로 VAD 값을 추출함
  • VAD를 EASV로 바꾸어 emotion feature로 사용함
  • 복잡한 emotion encoder 없이 emotion control을 단순화하려는 방향임

UDDETTS

  • discrete emotion label과 ADV/VAD 값을 함께 사용하는 LLM 기반 TTS 모델
  • label만 쓰는 방식의 표현 문제와 VAD만 쓰는 방식의 annotation 부족 문제를 함께 다룸
  • ADV 값을 token화하여 모델 조건으로 사용함

Laugh Now Cry Later / EmoCtrl-TTS

  • 감정이 시간에 따라 변하는 speech 생성에 초점을 둠
  • arousal / valence 값을 시간 흐름에 따라 사용함
  • 웃음, 울음 같은 non-verbal vocalization을 별도 embedding으로 다룸

Learning Emotion-Invariant Speaker Representations

  • speaker verification에서 감정 변화가 speaker embedding을 흔드는 문제를 다룸
  • 같은 화자의 다른 감정 발화를 embedding 공간에서 가깝게 만들도록 학습함
  • emotion-aware masking으로 감정 표현이 강한 구간의 영향을 줄임

EmoSpeechAuth

  • emotional speech 환경에서 speaker verification을 개선하려는 논문
  • speaker embedding과 emotion embedding을 함께 사용함
  • cross-attention으로 emotion 정보를 speaker verification에 활용함

F. 정리

  • 이미지 생성 분야는 instruction을 object, attribute, relation 등으로 나누어 평가
  • VA Prediction은 emotion을 label 하나가 아니라 V/A/D 연속 축으로 평가
  • Emotional TTS와 speaker verification 분야는 speaker, emotion/style, content를 나누어 모델링
  • 관련 논문들은 각 조건이 잘 유지되는지 확인하기 위해 별도 loss, encoder, metric을 사용함
